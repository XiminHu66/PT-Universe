# Personal VPS provider update — 2026-10-19

The public music page defaults to Monochrome's own Tracks search and FLAC URLs. BT and normal video links hand off to the dedicated account portal, then the existing outward-polling VPS Agent submits Aria2/MeTube jobs. No Owner key is pasted into the public page. Video extraction occurs on the VPS; the optional public-direct-link parser remains separate. Unsupported/login/DRM sources may still fail.

The personal account mode requires Owner-approved device pairing and keeps file streaming OFF. Default wrangler settings remain closed; activation is the explicit `account-personal-on` operation. The stable `media-vault-personal` realm preserves account/profile ownership across deployments. Session life is seven days, at most 200 newly created tasks per device session; this is an application limit, not provider allowance.

PikPak uses checksum-pinned official CLI v0.5.3 over stdio. Add multiple user-owned PAT profiles in the dedicated account page. Tokens use authenticated encryption in the D1 transport envelope and VPS credential vault, never browser storage. D1 removes the envelope after the registration reaches a terminal state. Use PikPak to revoke a token; the UI currently has no profile-removal control. A new token must be registered again after expiry/revocation.

Each PikPak video is at most 6,000,000,000 bytes, and downloads are serialized. Actual provider task, storage and third-party downstream quotas still apply. Verified size, optional provider GCID/MD5 and fsync precede any cloud cleanup. Only the newly created file in the task's unique folder may be moved to Trash. Existing/deduplicated/failed files are preserved. Official PATs cannot permanently purge Trash; users must permanently delete this task's file in PikPak to release storage. The app does not claim automatic quota release and never purges unrelated files or rotates accounts automatically.

Verification boundaries: local SQLite, protocol, mock UI and download fixtures are not real PikPak account acceptance. No real user PAT has been supplied. Monochrome metadata search succeeded; a bounded four-byte audio probe returned HTTP 403, so actual FLAC availability from this execution network is unverified. A real controlled BT WebSeed acceptance does not establish arbitrary magnet peer reachability. Actual VPS proof and deployment run URLs belong in the release record only after completion. The prior release's Windows native-save evidence and deferred cross-day/UI limits remain historical evidence, not acceptance of these new providers.

No new public listener. Password collection occurs only in the private account page after explicit storage consent. The cloud execution browser must not fetch the policy-blocked Worker `/app/` page; metadata/auth readiness checks and local fixtures do not substitute for user-device acceptance.

## 2026-10-19 complete-account cleanup update

The account page additionally accepts explicit consent to encrypted full-account storage. Username/password are encrypted in the D1 transit envelope, decrypted only by the VPS Agent and used by checksum-pinned official rclone v1.75.2. Temporary rclone config has mode 0600; persisted config remains AES-GCM encrypted. Registration must authenticate and obtain quota before it is listed. PAT profiles remain supported and cannot purge. Registration cancellation clears the transit envelope too.

Full-account downloads create an initially absent unique job folder, bind its provider ID, submit once, and download one video <=6 GB. The VPS copy must match provider MD5, or a separate remote SHA-256 read if MD5 is missing. No automatic permanent deletion: the completed task shows the exact name, bytes and file ID for an irreversible confirmation. Cleanup rechecks account/job/file identity, local SHA-256 and remote size/ID, then invokes only rclone deletefile in the bound folder. An uncertain deletion is never replayed; whole-account Trash is never purged. Quota release is separately reported as observed or pending.

The existing MeTube engine is updated to official release 2026.10.19, including its current yt-dlp and Deno runtime, after confirming no active adapter task. Existing data and port bindings are retained. BT continues through the existing Aria2 server. Actual availability of arbitrary torrents or provider-restricted videos is not guaranteed.

Tests use controlled credentials, files and mock provider responses. No real user full-account login, PikPak download, permanent deletion or quota release has been accepted yet. User credentials must be entered only in the private account page, never in chat. Live account HTML remains out of bounds for this execution browser; local Playwright fixtures are not user-device acceptance.
