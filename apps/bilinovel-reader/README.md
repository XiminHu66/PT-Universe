# 净读 · Bilinovel（VPS 按需版 3.1）

PT Universe 独立入口：`apps/bilinovel-reader/`，打开现有私有工具中心的 `/bilipack/reader/`。iPhone Chrome 可直接使用，无需书签脚本、扩展或另装浏览器。原站账号仅在 VPS 的专用浏览器配置中保留，不会自动继承手机 Chrome 的原站登录。

## 阅读与界面

紧凑本机书架，支持作品链接和数字编号；原站推荐、账号书架；真实目录的分卷、章节搜索、插图隐藏、当前章定位；正文支持四主题、字号、行距、段距、字体、缩进、对齐、宽度、滚动、左右分页和沉浸阅读。目录分批渲染，避免一次创建数千按钮。

导航同时验证目标路径和 CDP loaderId，防止读取上一个页面。目录仅从目录页的实际章节区域提取，并限定本书；上一页、下一页不会成为章节。打开作品或章节链接会归一到章首页，续读请求保留原站分页地址，防止「上一章」只读到该章最后一页。阅读器先返回单个原站分页，后续内容在接近底部或点击续读时读取，不再等待整章收齐。加载失败不会被当成登录或广告验证；原站确实要求登录时使用独立表单，密码不写入本机存储或服务器文件。正文过滤隐藏诱饵、图片与广告节点，保留真实重复台词。未加载、未授权的正文不作为成功结果。

## 资源边界

- 复用 BiliPack Node 服务和其浏览器；不增加容器、常驻任务、计划抓取、模型或新工作流。
- 普通正文、目录、书库返回后关闭阅读器自己创建的标签页。用户明确验证后，最多短时冻结复用同一标签以保留标签内会话；冻结时阻止全部网络，3 分钟无操作或返回书架时释放。文字排版、滚动、分页在手机本机完成；登录配置仍由已有浏览器保留。
- 一次串行读取；新会话检查 MemAvailable、磁盘 15% 保留线，下载繁忙时拒绝创建新阅读会话。不能把容器整体用量当成阅读器增量。
- 原站加载单页最多约 22 秒，整个读取任务有 65 秒预算，章节最多 16 页 / 40 万字；支持取消操作。
- 仅验证期间传屏，每 4 秒最多一次、每次一帧；截图不会延长会话寿命。切后台冻结验证页面、阻止新请求；3 分钟无用户操作后关闭会话。最多保留 4 个阅读器自己的原站页面。
- 正常读取允许原站文字 API/CDN、同源 blob 脚本及原站嵌入的两个初始化统计脚本；其余第三方资源及图片、媒体、字体继续屏蔽。广告验证仅用户主动放行；关闭验证恢复屏蔽并释放标签页。弹窗保留人工操作入口，不绕过验证码或授权。
- 设备本机最多缓存 12 章，约 3 MB；阅读位置最多 150 条，书架最多 60 本。服务器仅保留最多 16 个结果 / 3 MB、15 分钟有效的内存缓存，不额外保存正文库。浏览器个人配置目录仍属于已有服务，其缓存上限不代表整个配置目录的磁盘配额。

## 验证与部署

`node --test services/bilinovel-reader/*.test.mjs` 验证导航旧 DOM/loader、分页、会话释放、截图过期、冻结恢复、资源阈值、取消和 HTTP 边界。`scripts/bilinovel-reader/preview.mjs` 仅为本地 UI 回归提供明确标注的虚构内容，不进入生产资源。预览使用 Sites 管理的 dev 服务；`/qa/source` 检查目录/正文选择器，`/qa/mobile` 提供 390px 布局检查。

`python scripts/bilinovel-reader/assemble.py <现有BiliPack server.mjs>` 更新嵌入模块和资产。私有 ops 仓库沿用 31 工作流的 `repair` 应用更新分支：不重建下载引擎、不改其他服务配置，保留私有访问认证及回滚检查。发布前运行现有 Actions 资源策略检查。

浏览器样例测试不等于真实 iPhone、原站登录或广告验证验收；这些结果需要在上线后单独记录。v2 的本机书签脚本保留为旧文件，默认入口已恢复 VPS 方案。
