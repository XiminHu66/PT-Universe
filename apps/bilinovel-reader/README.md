# 净读 · 原站本机版（v2）

入口部署在 PT Universe 的 `apps/bilinovel-reader/`。v2 默认使用用户自己浏览器中的原站页面：登录、搜索、目录、授权和广告验证均在原站完成；脚本只重排已显示的文字。不使用 VPS 代理、CDP、截图、模型、定时抓取或数据库。

- iOS Safari：入口复制书签脚本，编辑一个书签的网址；每次打开章节后点书签。主屏幕快捷方式不能直接修改另一个站点。
- 已有用户脚本扩展：导入 `pt-bilinovel.user.js`；章节出现「净读」按钮，可在设置中选择自动进入。独立文件不远程加载代码。
- 书签版从同目录加载约 16 KB 的 `source-cleaner.js`，随后本机处理正文；静态托管仍有少量下载流量，原站正常加载仍使用用户设备资源与网络。
- 脚本隐藏阅读层广告、插图及 CSS 隐藏的诱饵文字，保留真实重复文字。它不拦截原站已经发出的广告请求，不下载整本书，不改变验证要求。
- 「原站 / 验证」移除阅读层，保留原站 DOM、账号状态与滚动样式。主题、排版、最多 100 个页面的阅读位置存在原站 localStorage；不存储正文。各域名的设置独立。
- 翻页和目录导航使用原站 `ReadParams` 的经过白名单校验的 URL，不自行拼接目录或提前抓取章节。源站改版时可能需更新选择器。

修改 `core.js` 后执行 `node scripts/bilinovel-reader/build-local.mjs` 生成两个发行文件。浏览器回归样例：`services/bilinovel-reader/local-browser-test.html`（通过静态预览访问）。已做 Chromium 的 DOM、交互与恢复检查；未做真实 iPhone Safari 登录/广告验证验收，书签脚本可能受浏览器或原站 CSP 影响，扩展版是可选替代。

旧 `/bilipack/reader/` 入口跳转此静态页，旧远程 API 返回 410。现有 BiliPack 更新仅在启动时关闭其独立 reader target，不创建新浏览器页面，不停止其他工具共用的 Chromium，也不改变小说下载功能。无新增工作流、计划任务或服务。
