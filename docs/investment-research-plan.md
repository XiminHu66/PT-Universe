# 投资研究台改造建议（方案，尚未实施）

当前 Thesis Lab 已有季度指标和手工论点，但历史覆盖有限，缺少可追溯的变化分析、估值假设和明确的观察条件。继续堆手填表单不会改善核心用途。

## 建议的工作流

1. **研究数据库**：以公司、财季、指标、申报时间和抓取时间存储实际值。保留原始来源、GAAP/调整口径、单位与重述版本。首先覆盖现有观察公司的可核验季度，不把 Yahoo 约五个季度的接口包装成长历史数据库。历史补齐需另行验证 SEC 或其他实际可获取来源。
2. **本季发生了什么**：收入、利润率、自由现金流、SBC、稀释股数的同比/环比，以及可取得的应收、存货、现金和负债。每条判断附计算、基期、来源、异常和缺失项。不同产业采用不同规则，缺失数据不会填零。
3. **价格是否值得研究**：实时价格与悲观/基准/乐观三种估值情景；展示未来盈利或现金流假设、合理倍数、目标价范围、安全边际和敏感性。用户偏好的“一年 30–40% 潜在上行”作为可调筛选门槛，不是收益承诺或自动买入指令。
4. **接下来观察什么**：输出需核实、进入研究区间、基本面改善/恶化等状态，并说明原因、触发条件、下次财报和反证条件。保留每次分析快照，之后能检验当时的假设。

## 首页应直接回答

- 哪些公司出现值得关注的季度变化？
- 哪些公司的当前价格进入自己设定的研究区间？
- 哪个估值假设最敏感，什么新事实会推翻判断？
- 本次与上次结论为何不同？

## 轻量实现

GitHub Actions 负责有来源的日更/财报更新；SQLite 保存结构化历史，并导出小型 JSON 供 Pages 查询。已有 Worker 提供有限的即时价格查询。先实现可复算的分析规则，不依赖 LLM 写出无法核验的买卖建议。自然语言说明如以后接入模型，也只能解释已计算结果并列出来源。

建议第一版先覆盖 NVDA、MSFT、GOOGL、META、AMD、AVGO 等重点公司，验证三个真实案例：业绩改善但估值偏高；增速放缓但价格已反映；现金流与会计利润明显背离。通过这些案例后再扩大覆盖和自动化建议。
