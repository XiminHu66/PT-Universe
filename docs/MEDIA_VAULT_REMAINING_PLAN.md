# Media Vault 原始计划与集成候选检查点

此文件是原计划的续接索引，不重新编号已经执行的步骤。
第 22 步为 Oracle VPS 出站代理部署与启动；之后始终按元数据、文件传输、
恢复与额度、真实来源、前端接入、合并发布推进。账号配对是无需复制长期密钥
使用这些功能的前置工作，不是替代下载项目的新目标。

## 原始目标和约束

- 接入现有 Media Vault：小说 EPUB、中文漫画 CBZ、视频和 Aria2/BT。
- Cloudflare HTTPS Worker + D1 保存队列、元数据和传输账本；VPS 主动出站。
- 不需要自有域名，不新增公网应用端口。
- 下载最终由浏览器保存到本机；媒体不归档到 Cloudflare、GitHub 或 Actions Artifacts。
- VPS 临时空间上限 12 GiB，正常保留窗口 24 小时；活动传输、元数据不可用或身份
  不符时按既有保护规则延后清理。收到流式 ACK 不代表本机磁盘保存完成，不立即删源。
- Media Vault 自设传输预算 100 GiB/月，页面显示真实已用、预留和剩余，不冒充云厂商账单。
- 默认关闭流式传输和账号访问。生产页面、合并发布是单独的最终决策。

## 本轮集成候选的实质变更

1. Owner 与账号入口共用规范化任务契约：丢弃外部 request_id、headers、account_id
   等未支持字段；提前拒绝重复章节、无效布尔/排版参数和无效 JSON；保留既有 Owner
   `skip_images` 布尔选项。小说章节排序后保存，重建仍克隆服务器原请求。
2. 内容取消在目录、章节、插图请求边界和来源等待期间检查，避免已取消任务再请求
   下一章/下一图。小说与 CBZ 在累计正文/图片达到既有 100 MiB 内容上限时提前停止；
   过长段落明确失败，不依赖打包器截断。另修复先过滤换行导致段落粘连的问题，
   保留独立段落，去掉空段，不改动正常正文。
3. 增加必须提供两个组件源码的离线集成命令，实际运行账号客户端/表单、Worker、
   SQLite、Agent 轮询、适配器和 EPUB/CBZ 打包，再把报告送回 Worker 查询文件。
   检查取消、重建、重启不重复提交、退出、零票据和零传输账本。
4. 新增无部署的候选检查工作流、来源版本固定的伴随组件检查，以及机器可读的
   `candidate-manifest.json`。候选检查保护关闭默认值、100 GiB 预算、排版契约和
   本轮未修改的生产入口源码；`candidate-check.mjs --release` 在待办未清空时拒绝发布。

离线检查使用来源与视频/BT 引擎夹具；EPUB/CBZ 由真实打包器生成并检查。
这不是远程页面交互、真实新来源或 Windows 磁盘结果的证据。
候选代码提交与线上运行版本分开记录，本轮不部署 Worker/VPS，不开临时访问窗口。

## 可重复运行的检查

```sh
npm test --prefix workers/media-vault-hybrid
node workers/media-vault-hybrid/candidate-check.mjs
MEDIA_ADAPTER_SOURCE=/absolute/path/to/adapter-source \
MEDIA_AGENT_SOURCE=/absolute/path/to/agent-source \
  npm run test:integration --prefix workers/media-vault-hybrid
```

`test:integration` 缺少任一组件源码就失败，不把缺失组件作为跳过后通过。
工作流 `candidate-check` 不使用生产凭据、不执行 SSH、迁移、部署或线上请求。
未解决验收存在时，候选通过会明确输出 `NOT READY FOR PRODUCTION`。
这个检查是候选交付约束，不代表 GitHub 分支保护已被配置。

## 完整后续执行清单

1. 将本轮两个组件的修复作为配套候选审查；后续部署时一起更新，保留所有访问与流式
   开关关闭，并验证版本一致。不能只替换新增依赖验证函数的单个适配器文件。
2. 在浏览器访问能力可用的条件下完成原本的固定小说操作验收：一本书、前两章、纯文字、
   三种排版、取消和重建，总计不超过四项任务、一个设备、30 分钟、零文件票据。
   未经具体范围确认不自动重开窗口；结束后退出/撤销、关闭和对账。
3. 完成用户 Windows 浏览器的实际本机保存，并明确文件、字节/票据上限、期限和关闭动作；
   不能重置或重用已消费的三票额度。长时间设备保持需另行观察，不用时间模拟冒充实测。
4. 完成更广的中文漫画来源选择、可用性和接口适配，真实章节下载与 CBZ 结构/内容校验。
   保留来源访问与限流结果，不绕过限制，不把 Commons 样例作为通用站点支持。
5. 汇总上述证据，复核已有 Media Vault 到专用 HTTPS 账号入口的使用路径、恢复提示、
   剩余额度和本机保存体验；发布前保留源站登录与设备登录的区别。
6. 进行最终审查并取得独立的合并/生产发布决定，之后才发布入口和启用批准的权限范围。
   PR 104 以及伴随组件 PR 在此之前保持草稿。
