# 下载通道与本机保存验收

Windows 实机曾遇到原生下载停在零字节、后续点击无进展。此前 Windows CI 的
本地下载夹具通过，并未覆盖专用出站通道空闲后的状态，因此本人设备验收仍未通过。
详细日志与临时窗口记录只保留在私有运维仓库；不把失败写成已验收。

本轮修复：

- Agent 发送应用层心跳；服务端以连接附件保存最近活动和失效标记，空闲唤醒后仍可判断。
  超过租期的旧连接不能阻挡重新连接，也不能在替换后自行复活。
- 签发三文件验收票据前，必须通过当前连接的请求/响应探活。离线、无响应或正在传输
  时不签票、不占用本轮票据额度；探活超时有上限，待处理探活数量也受限。
- 新传输未收到首批字节时最多等待十五秒，随后失败结算并释放占用；后续背压仍按原
  边界处理。故障不会清空历史票据、账本或删除源文件。
- 页面分别显示“文件已生成”、通道离线/忙碌/已响应，以及“已交给浏览器”；
  后者仍不等于写盘完成。通道未就绪时不显示为可保存，失败不会建议靠重配对恢复额度。

相关检查包含真实 SQLite、实际 workerd WebSocket/FixedLengthStream，以及实际 Python
Agent 的真实超过一分钟空闲、心跳、传输、强制断开和重新连接。来源 I/O 是本地微型
夹具，不访问生产、不代表用户 Windows 复验或真正长期设备观察完成。

恢复原则：保持默认关闭，不复用或重置已消费窗口。修复回归后只部署关闭候选。
新的实机下载需另有明确的文件/设备/票据/字节/期限范围，再以本机下载和离线报告验收。
小说真实页面操作、用户设备保存、真实长期会话与独立发布决定继续保留。
