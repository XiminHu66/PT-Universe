## 当前已上线

- 视频、BT 和 PikPak 的提交、状态、取消、重试与保存留在 Media Vault 页面。
- 使用现有私有 GitHub 身份应用登录，仅限已有所有者身份，无仓库读写权限；不通过公开 issue 授权，不逐次回聊天批准下载。
- 视频由 VPS 的 MeTube / yt-dlp 下载，BT 由 VPS 的 Aria2 下载；Agent 复用出站 WSS，没有新增 VPS 公网应用端口。
- 正常鉴权文件交付已启用。早期“保持流式传输关闭”阶段已被后续批准的正常交付取代。关闭默认配置和历史 workflow 名称不代表线上关闭。
- 视频先登记任务再异步解析；页面区分排队、解析、BT 元数据、等待来源、下载与合并。确认取消或失败后，同输入重试创建新任务。
- 所有交付模式签发票据前探测连接；经过鉴权的新连接可替换半开连接。只在确认尚未交付数据时有限自动恢复，不自动重放不确定的部分下载。
- Monochrome 是 FLAC 默认来源。PikPak 支持多个加密保存的自有账号，每项最多 6,000,000,000 字节。
- PikPak 完整登录支持核对具体任务文件后另行确认永久删除；PAT 仅支持回收站。删除结果不确定时不自动重放，不清空整个账号回收站；删除结果与额度释放分别显示。

保留每月 100 GiB 自定流量预算、12 GiB VPS 工作区上限、根分区至少 21 GiB 预留和临时文件 24 小时保留。用户无需本地服务密钥。凭据只在账号表单输入，不进入公开仓库、聊天、浏览器存储或任务日志。

## 剩余真实使用验收与继续顺序

1. **PikPak 完整闭环**：尚无本轮真实用户完整登录、永久删除和额度释放证据。在视频页“用 PikPak 下载”中添加自有账号、选择账号及有权保存的测试链接；VPS 下载校验后，核对对应文件再确认永久删除。逐项验收，不把模拟接口当作真实完成，不在聊天索取密码。
2. **Monochrome FLAC**：默认来源和元数据已实现；此前执行环境音频探测返回 HTTP 403。用户曾确认 FLAC 下载可用，但未确认切换后的 Monochrome 来源。仍须确认用户浏览器能从该来源保存并播放实际 FLAC。
3. **具体视频与 BT 来源**：受控样本和公开磁力证明基础链路可用，不代表任意站点、需登录的视频或无在线来源的磁力均可下载。DRM、地区及站点登录限制不属于已解决事项。具体失败只记录安全错误类别与任务阶段，不输出私密链接或无限重试。

继续顺序：保留线上版本及既有会话 → 原页面完成真实提供方使用验收 → 针对明确失败修复 → 运行相关测试 → 保持授权范围、公网端口和预算发布。没有新失败证据时无需重复部署或重新索取密钥。
